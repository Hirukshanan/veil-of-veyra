# Chapter I — Phase 0 repository audit

Date: 2026-11-13 (Asia/Colombo). Scope: existing local game, documentation and baseline verification only.

## Baseline and confidence

The actual project is **Veil of Veyra**, a Godot/GDScript third-person action-RPG prototype. The installed executable reports `4.7.2.stable.official.ed1daf0bf`. `project.godot` selects GL Compatibility, a 1280 x 720 landscape viewport and `scenes/main.tscn`; that scene attaches `scripts/campaign.gd`, which extends `scripts/main.gd`. Most gameplay scenery/UI is constructed by scripts, rather than separate authored level/prefab scenes.

Sources inspected: README, release status, validation history, Android setup, game design, project/scene configuration, campaign/player/enemy/boss/visual/terrain/forest/exploration/quest/persistence scripts, existing tests, and asset attribution files. Historical README/release statements are not treated as fresh test results. Older release notes still mention sequential chapters, NPCs and an on-screen lock button; current campaign code and current regression checks take precedence.

Labels below mean: **verified** = the stated behavior was exercised by a named local check; **partial** = useful implementation exists but falls short of the requested experience; **absent** = no active implementation found in inspected source; **unknown** = evidence/access is insufficient. Verification is desktop-only unless explicitly stated.

## Required reconciliation before later implementation

1. Keep Aru, existing seal mechanics, optional grove/bounty content, working sea and current island. The plan's sub-area names and lantern lore are proposals, not a mandate to erase stronger existing content.
2. Preserve the exact charcoal-black/ivory-horned dragon and skinned eye fix. Convert its role only in the later approved boss/reveal phase; do not add a second competing dragon.
3. Plan a versioned migration for old `completed` journeys before replacing Dragon victory with Bear victory. Keep earned shards/equipment/seals and one-time rewards; explicitly agree how already-completed journeys see the new story/reveal. Never reset personal saves to satisfy a test.
4. The local licensed asset makes all five ordinary enemies wolves. Separate fox identity or additional species requires a deliberate asset/behavior decision, not a health change based on historical prose.
5. The removed sixth spawn remains retired. No mandatory quest NPC should return.

## Fresh visual/performance evidence

Seven native GL Compatibility PNGs were rendered and reviewed: `arrival_hud`, `island_overview`, `forest`, `beach`, `ruins`, `dragon_identity_inspection`, `dragon_eye_inspection`, under the ignored evidence directory. The coast is visibly free of a tree wall, the forest/ruins/paths exist, the arrival hero is still a largely unclothed temporary base body, and the Dragon retains visible ivory horns and a glowing eye. This is baseline evidence, not finished-art approval. The overview temporarily disables forest distance culling solely for inspection; runtime culling was not edited.

A 120-frame stationary arrival sample in a minimized native window using explicit `force_draw` recorded 534 draw calls, 646,633 primitives, median frame interval 43.463 ms, p95 48.453 ms and maximum 52.322 ms. These method-specific desktop intervals are not gameplay or phone FPS benchmarks and do not establish the 30-FPS mobile target. Do not compare them directly to earlier samples with different render/window methods. Main-route and handset/thermal profiling remains open.

28/28 selected existing regression checks passed. Heavy-attack and sprint tests each emitted a two-ObjectDB-instance shutdown warning, despite passing behavior assertions. The full coastal check passed on a longer retry after the initial harness timeout. See `CH1_TEST_MATRIX.md` for full evidence and `CH1_PHASE0_REPORT.md` for the phase review.

## Concrete next phase proposal — Phase 1 only

**Goal:** connect the existing useful places into a readable Chapter I route, while reserving space for the later Bear/reveal work.

- Document existing arrival (0,0,27), central forest/waystones, Tideseal Ruins (-44,0,54), Moonleaf Grove (44,0,28), hills and northern ruins. Keep optional Moonleaf objectives intact; do not automatically turn their clearing into the boss arena.
- Inspect and improve only obstructed/unclear connections in `scripts/island_terrain.gd::trails`, `scripts/island_exploration.gd` and, if needed, `scripts/island_forest.gd` clearing exclusions. Reuse working hills, tree meshes, collision and sea shader.
- Choose a small boss-clearing footprint and a distant dragon viewpoint/camera anchor within the current island after route sightline inspection. Reserve/document them; do not spawn a Bear or create the cinematic yet. Add subtle map landmarks in `scripts/island_map.gd` only if they aid navigation.
- Add a focused route regression only where new routes/clearings are changed; rerun existing regions, navigation, collision, camera, grove, seal, water and save checks. Capture the complete out-and-back route and request phone measurements when hardware is connected.
- Expected files: the scripts above only where evidence calls for a change, `docs/CH1_REGION_LAYOUT.md`, and relevant existing route tests. Exact placement should follow sightline review rather than speculative wholesale terrain edits.

**Risks:** foliage expansion can raise draw/memory cost; terrain changes can bury saved positions; new rock/tree placement can block quest pickups/camera. Mitigation: keep terrain radii/heights and quest IDs/locations stable by default, retain obstacle collision, compare fresh/returning saves and baseline renders/counters. No new external assets or save schema changes are expected in Phase 1. Rollback uses a local scoped patch of that phase's files, retaining the pre-existing dirty tree. Never whole-tree reset.

**Review gate:** Phase 1 is proposed, not implemented. The owner requested phased work; this audit is the reviewable first result. No later chapter content is authorized by this proposal.
